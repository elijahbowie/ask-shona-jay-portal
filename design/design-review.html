Findings & remedies

Seven fixes, each tied to a standard

P1Accessibility · WCAG 1.4.1

Admin review severity was conveyed by color alone

Symptom
High / medium / low severity showed only as a colored left border. Color-blind and screen-reader users could not tell them apart.
Fix
Added a labelled severity-tag pill (text + color), replaced the banned border-left:3px side-stripe with an inset edge as a redundant cue.
Evidence
Verified in-browser: HIGH (red) / MEDIUM (amber) / LOW (sky) pills read correctly at 1200px and 390px.
P1UX · own RATIONALE §15

Learn library had no empty state for zero search results

Symptom
Searching for a non-match collapsed the grid to a bare border line — the exact "No results with no guidance" failure the rationale forbids.
Fix
Added a named empty state ("No pages match your search" + a Clear-search action) and a 4-card loading skeleton so the grid never flashes empty during fetch.
Evidence
Renders with guidance copy and recovery button; guarded so it only appears after load, never during.
P1Responsive bug

Admin Assets table overflowed on mobile

Symptom
An inline gridTemplateColumns style outranked the mobile media query, so the 4-column table could not collapse and clipped the Download/Delete actions off-screen.
Fix
Moved columns into CSS (.assets-table .asset-row), decoupled from the generic collapse rule, and collapsed to Title + Actions on small screens.
Evidence
At 390px the table now shows Title + Actions; Lesson and File drop cleanly, actions stay tappable.
P2UX · own RATIONALE §7

Escalation CTA never "flipped to a calm confirmed state"

Symptom
After sending, the "Want Shona to review?" button kept its amber alarm styling — only the text changed — and could be clicked again, firing a duplicate escalation.
Fix
Confirmed state now uses a calm success treatment with a check icon and is disabled to prevent a duplicate POST.
Evidence
Default amber vs. confirmed green verified side-by-side in browser.
P2Accessibility · WCAG 1.4.3

Placeholder text failed AA contrast

Symptom
Placeholders used --ink-quaternary (#8590a8 ≈ 3.1:1) against white — below the 4.5:1 text minimum.
Fix
Placeholders now use --ink-tertiary (5.4:1) with opacity:1, still clearly lighter than entered navy text.
P2Accessibility · 4.1.2

Library search input had no accessible name

Symptom
The search relied on placeholder text only; assistive tech announced an unlabelled field.
Fix
Added type="search", an aria-label, role="search" on the wrapper, and hid the decorative icon from the a11y tree.
P3Anti-pattern hygiene

Decorative side-stripe on citation cards

Symptom
Citation cards carried a 3px sky left-stripe — a flagged decorative anti-pattern that adds no information.
Fix
Removed the stripe; the "sourced" brand cue is now carried by the source-type label in brand sky. Full hairline border retained.
Considered & deliberately retained

Where the panel chose restraint

Conceptual integrity outranks reflexive rule-following. Three things a generic pass would have "fixed" were left alone because the product defends them on purpose.

Section eyebrows / mini-labels on every surface

A generic audit flags repeated uppercase kickers as an AI tell. Here they are a deliberate, consistent wayfinding system (recognition-over-recall) used identically across client and admin. Kept as voice, not grammar.

Density of the Ask page

Deadline, readiness ring, memory card, prompt builder and free-text input coexist by design (loss aversion, goal-gradient, choice architecture, all named in the rationale). Restructuring would fight an intentional, defended composition. Flagged as a watch-item, not changed.

Blockquote left rule in the reader

A left rule on a blockquote is canonical typography, not a decorative side-stripe. Changing it would surprise content authors for no reader benefit.
